     GUI Editor Rewrite — Dual-File Heteronym Manager

     Context

     The current HeteronymDictionaryManager
     (bookfix/dialogs/heteronym_manager.py, 902 lines) edits only
     choices_pos_dictionary.json. Adding or editing a homograph requires the
     user to also manually edit choices.json in a text editor. The rewrite makes
     the dialog edit both files at once for a selected word — one place, one
     save.

     What the rewrite does

     The dialog gets a second data panel alongside the existing pos_dictionary
     panel. For each word, the editor shows the choices.json data (definitions,
     keywords, NLI hypothesis) and the pos_dictionary data (dep_rules, pos_tags)
     together, grouped by pronunciation spelling. Saving writes both files.

     Layout

     Three regions:
     1. Left column: word list (all words sourced from choices.json, which is
     the single source of truth for which words exist)
     2. Right column, top: one group box per pronunciation spelling — each group
     box contains a choices.json sub-section and a pos_dictionary sub-section
     side by side or stacked
     3. Bottom bar: Save, Add Word, Delete Word, navigation (Prev/Next), and
     Generate with AI buttons

     The word list populates from choices.json on load. If a word exists in
     choices.json but has no pos_dictionary entry, the pos_dictionary
     sub-section shows blank/empty fields.

     Fields per pronunciation spelling

     choices.json sub-section (left or top within the group box):
     - Definition — single-line text field
     - POS (coarse) — single-line: VERB, NOUN, ADJECTIVE, Other
     - Strong keywords — multi-line text area, one per line
     - Context keywords — multi-line text area, one per line
     - Examples — multi-line text area, one per line
     - NLI hypothesis — single-line text field

     pos_dictionary sub-section (right or bottom within the group box):
     - POS tags — single-line, comma-separated (VBD, VBN, etc.)
     - Description — single-line
     - Context keywords — multi-line text area, one per line
     - Dep rules — multi-line text area, raw JSON (too structured to break into
     sub-fields)
     - Match mode — dropdown: "all" / "any"
     - Auto-generated badge — read-only label shown only when auto_generated:
     true in the data

     Data loading

     On word selection, load from both files:
     - Find the word's entry in choices.json options array (matched by spelling)
     - Find the word's entry in choices_pos_dictionary.json words dict (matched
     by word key, then spelling key)
     - Populate all fields; leave pos_dictionary fields blank if no entry exists

     Saving

     On Save:
     - Read the current text from all fields
     - Update the in-memory choices.json entry for this word (replace the full
     options array)
     - Update the in-memory pos_dictionary entry for this word (replace the full
     spelling dict)
     - Write choices.json to data/choices.json
     - Write pos_dictionary to ~/.ai_learning/choices_pos_dictionary.json
     - Validate JSON before writing (esp. dep_rules field) — show error dialog
     if invalid, do not write

     Adding a new word

     Add Word button: prompts for a word name, creates a blank entry in both
     in-memory dicts with one default spelling, switches to that word in the
     list.

     Files to modify

     Primary rewrite: bookfix/dialogs/heteronym_manager.py
     Data sources: data/choices.json (read + write),
     ~/.ai_learning/choices_pos_dictionary.json (read + write)
     No other files need changes — the dialog is launched from gui.py and the
     launch call doesn't need to change.
